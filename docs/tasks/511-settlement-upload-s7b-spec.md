## Rulings
1. **Approve lives only on the day detail of a PENDING day**, never on a row, never "approve all". A day with blockers shows NO button: the existing blocker list stays and one muted line says what is missing ("Fix the items above first."). When the actor may not approve, no button and one plain sentence: the actor uploaded a file this day comes from ("You uploaded a file this day comes from, so someone else must approve it.") or lacks permission (existing wording). `approveDay` stays the backstop.
2. **Domain adds (small readers on the existing review layer, `packages/domain/src/settlement-intake/review.ts`):** `ReviewDayDetail` gains `canApprove` + `approveWhy` (computed from `can(record_ar_collection, store)` and `uploaderIdsOfLine` vs actor; admin via `override_period_lock`, same test as `reopenDay`; no names, no ids leave the server), `isCarrier` + `carrierNote`, `invoiceCharges` (the invoice's staged period charges with state: not booked / booked / replaced by a newer upload / cannot be booked, with the plain reason `postPlatformCharge` would give, incl. the "same copy already booked" case), and for a booked day `bookedOn` (date) with the sentence to undo (an admin cancels the settlement on the Overview tab; the day then returns here as waiting; S7a). New reader `listPeriodCharges` for the section "Charges not tied to a day" (every staged period charge of the actor's visible stores, posted or not, newest first, invoice number, charge date, description, net, VAT, total, state, `canBook`); this covers the fee-only invoice that has no day row. The carrier note says: "This payout also settles {N} charge(s) of this invoice. The bank deposit is the file's net minus {total}." Charges panel shows the invoice's charges on every day of the invoice; only the carrier day carries the note.
3. **`bookPeriodCharge(tx, actor, { otherLineId })`** (new, in the review layer; `postPlatformCharge` is NOT changed, S6c stays closed): applies the uploader rule to the charge's upload (non-admin who uploaded it is refused, plain words, no store named; admin via `override_period_lock` exempt) and then calls `postPlatformCharge`. The action calls `bookPeriodCharge`, so `postPlatformCharge` stays an INTERNAL wrapper row in `domain-actions-have-callers`.
4. **Actions** (`review/actions.ts`), written exactly like the existing reject/reopen (discovery: `requireActor()` first → `lineId` + `navOf` → `try { withOrgPrincipal(actor.orgId, tx => domainFn) } catch (err) { redirectWithFlash(REVIEW, nav, { error: errorMessage(err) }) }` → success `redirectWithFlash(..., { ok, stamp: 'POSTED' })` AFTER the try; no `throw`, no `new Error(`, no `assertFieldRules` in the action): `approveDayAction` (reads `lineId`, optional `differenceReason`, optional `confirmedDifference`) and `bookChargeAction` (reads `otherLineId`). Inside the catch of `approveDayAction`: when the error is `SettlementIntakeRefusal` with code `NEEDS_REASON`, redirect with the nav key `ack` = `{short|over}-{difference}` (see 5) and NO error banner of its own (the page shows the reason form).
5. **NEEDS_REASON round trip.** Add ONE closed nav shape `ack` in `lib/flash.ts` (`^(short|over)-[0-9]{1,12}\.[0-9]{2}$`, with its test; the nav shapes are a deliberate allow-list). The page, for a pending day with a well-shaped `ack` for THAT day, renders a SECOND form (its own `CheckedForm rules={SETTLEMENT_DIFFERENCE_RULES}` with `<Field rule>` + `<Textarea {...nativeAttrs(...reason)}>`, hidden `lineId`, hidden `confirmedDifference` = the figure from `ack`, submit "Approve and book") above the plain Approve; the sentence is the SettlementForm wording rebuilt for this screen: "The payout is {money} {short of | more than} the day. That is past the tolerance. Accept it only if … It is booked as {an expense (settlement variance) | income (settlement gain)}." The reason text is NOT refilled after a refusal (same as reject; test pins). The URL figure is only what the person saw: the domain re-computes and refuses again if it differs (S7a ruling), so a forged `ack` cannot book a different amount than the person confirmed.
6. **Labels:** "Approve and book" and "Book this charge" are the submit labels; add them to the `COMMANDS` list in `t384-s3-lock-and-save-guard.test.ts` (G8) and flag the pin change to BOSS in the hand-back. Success flash `ok` sentences in plain words ("Booked. The day's payout is on the books and the sales figure now matches the file." / "Charge booked.").
