## Scope

**`stage.ts`** (pure, no db): `stageFoodpandaDays(invoice, matched)` and `stageGrabDays(tied, transactions)` -> `StagedDay[]` (day line fields + loan lines + other lines + warnings). Rules (design:494, decisions 15-16): `order_value` is NET as staff record it (Foodpanda column R summed per Order Date; Grab Net Sales); `gross_info`, `vendor_discount` information only, never booked; commission columns -> `commission`; Grab Advertisement rows and Foodpanda CPC ads -> `marketing`; everything else -> `platformFee` through `deductionFor` (the mapping table, never a second copy); Foodpanda weekly Platform Fee goes to the invoice's last sales day, relocated to the nearest earlier day whose order value less its own fees covers it, with `fee_month_note` kept; PandaGO -> `none` (other line kind `pandago`, `booked_as` none); Grab loan rows -> loan lines (kind deduction or disbursal, `amount` magnitude > 0, `row_ordinal`, `loan_id` null: S4 never allocates); a disbursal is excluded from the deposit (`net_payout` is the sales part: Lipa 13 Oct payout 154,473.51 stages `loan_disbursal` 150,000 and `net_payout` 4,473.51); `unexplained` = payout less (order_value less all fees plus credits) when not zero (marks the line, never refuses). **`ingest.ts`** (domain; `ingestSettlementFile(tx, actor, { bytes, contentType, fileName? }): Promise<IngestResult>`, tx non-nullable; the upload action opens ONE `withOrgPrincipal` per file so a failed file rolls back alone and the batch reports per file):

Audit entry `settlement_upload.ingested` (catalogue entry + ceiling bump per census). 13. ## Opus rulings after the tester's contract choices (4 Nov; the tests encode these)
1. `stage` returns `StagedFile { days, periodLines, waitingForRows }` (a PandaGO-only invoice has lines and no day). Accepted; replaces `StagedDay[]` in the text above.
2. Amount signs: cost positive, credit negative; Grab other-line amount = minus the row Total; Foodpanda = printed Net Total; Grab loan lines are magnitudes, `rowOrdinal` increases in file order.
3. Grab `unexplained` = `netPayout - (orderValue - commission - marketing - platformFee - loanDeduction)` (the loan deduction is part of it; the spec formula above was missing it; Lipa 13 Oct only reaches 0.00 with it).
4. Foodpanda `netPayout` = day balance less that day's CPC ads less the weekly Platform Fee placed on it, so `unexplained` is 0.00 on all five real invoices; `vendorDiscount` = O+P+Q. This is the one rule not proven against a bank payout: BOSS confirms at hand-back.
5. `difference` = `order_value - recorded_figure` (Lipa 20 Oct: +454.00). The "waiting for the sales day to be verified" state has no column: null snapshots plus the warning sentence.
6. **The PDF is NOT stored in S4**: `limits.ts:46` allows only csv and zip for `channel_settlement_file`, a slice-2 test pins that a PDF is refused, and the original zip (which contains the PDF) is already stored whole. `pdf_file_id` stays null; no limits change.
7. Repeat-fingerprint lookup runs after the fine gate and BEFORE `uploadFile` (no second stored copy): extra repo function `findUploadByFingerprint`; also `currentLine`. Accepted.
8. A booked line replaced by a changed upload: the booked row keeps every column except `is_current` (the unique current index forces it false). Accepted.
9. Spec item 13 second warning (Foodpanda day outside open sales days) is DROPPED: no testable definition. The fewer-days warning stays. Recorded as a follow-up for slice 5 if the review screen needs it.
