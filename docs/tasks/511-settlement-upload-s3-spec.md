## Scope (all in `packages/domain/src/settlement-intake/`, one barrel `index.ts`)
1. `refusal.ts`: `SettlementIntakeRefusal` with an UPPER_SNAKE `code`, built like `leave/refusal.ts` (`refuse(sentence, sentence)` wrapped). Sentences never contain a Store ID or any UUID (`refuse()` redacts every UUID to `[hidden]`; core/src/sentence.ts). Codes: `FILE_EMPTY`, `FILE_TOO_BIG`, `ZIP_NOT_A_ZIP`, `ZIP_TOO_MANY_ENTRIES`, `ZIP_TOO_BIG_EXPANDED`, `ZIP_UNSAFE_NAME`, `ZIP_NESTED_ARCHIVE`, `ZIP_ENTRY_NOT_ALLOWED`, `ZIP_SIZE_MISMATCH`, `ZIP_NO_WORKBOOK`, `GRAB_MISSING_COLUMN`, `GRAB_UNKNOWN_COLUMN`, `GRAB_BAD_ROW`, `GRAB_BAD_VALUE`, `GRAB_UNKNOWN_VALUE`, `GRAB_MIXED_STORES`, `GRAB_TOO_MANY_ROWS`, `GRAB_NO_ROWS`, `FOODPANDA_MISSING_COLUMN`, `FOODPANDA_UNKNOWN_COLUMN`, `FOODPANDA_UNKNOWN_LAYOUT`, `FOODPANDA_NO_SHEETS`, `FOODPANDA_MIXED_INVOICE`, `FOODPANDA_TOO_MANY_ROWS`, `FOODPANDA_BAD_VALUE`. Each refusal names the column, value or line, never a customer or order id. Raw `throw new Error` is forbidden in the folder (throw ratchet).
2. `safe-zip.ts`: `openSettlementZip(zip: Buffer): Promise<{ workbook: Buffer; pdf: Buffer | null }>` and `normalizeXlsx(workbook: Buffer): Promise<Buffer>` (the checks plus a re-pack, see below). yauzl `fromBuffer` with `lazyEntries` and `validateEntrySizes`. Order of checks (pinned by tests): length 0 -> `FILE_EMPTY`; buffer over 1 MB -> `FILE_TOO_BIG`; open fails -> `ZIP_NOT_A_ZIP`; yauzl's own unsafe-name refusal at open -> `ZIP_UNSAFE_NAME` (never extract to disk); entry count over 10 -> `ZIP_TOO_MANY_ENTRIES` (from the listing); any entry whose name ends `.zip`, `.xlsx`, `.gz`, `.7z`, `.rar` or `.tar` -> `ZIP_NESTED_ARCHIVE` (checked BEFORE the allow-list); any name that is not `.xls` or `.pdf` -> `ZIP_ENTRY_NOT_ALLOWED` naming the entry; sum of DECLARED uncompressed sizes over 5 MB -> `ZIP_TOO_BIG_EXPANDED` (nothing inflated); then READ every entry with a running byte cap of 5 MB and yauzl size validation -> `ZIP_SIZE_MISMATCH`; only THEN require exactly one `.xls` -> `ZIP_NO_WORKBOOK` (so the lying-size zip, which has only a pdf, still reports the size problem). `normalizeXlsx` runs the same listing and streaming checks on the inner workbook (max 30 entries, 8 MB expanded: raised from 5 MB on 4 Nov because a 5,001-row sheet expands to about 6.8 MB and the 5,000-row cap must stay reachable; real max 437 KB) BEFORE `read-excel-file` sees it, because neither xlsx library caps its own inflation. It then RE-PACKS the validated `.xml` and `.rels` parts into a fresh STORED zip with true sizes (no other parts, duplicate names refused as `XLSX_MALFORMED`, `zip-repack.ts`) and returns that Buffer: the library walks LOCAL headers and allocates what they declare, so only the re-packed zip may be given to the worker. No time limit (unenforceable on a synchronous parse; if a slow file ever appears, a worker thread is the fix: recorded).
3. `grab-transactions.ts`: `readGrabTransactions(bytes: Buffer): GrabTransactionsFile`. Decode UTF-8 strictly (`fatal: true`, BOM stripped), `parseCsv` from `@shareat/core/csv` (a CSV unclosed-quote error becomes `GRAB_BAD_ROW`). Header: trim each header; the file must have exactly the 68 known headers (missing -> `GRAB_MISSING_COLUMN` naming the header; extra -> `GRAB_UNKNOWN_COLUMN` naming it); map by name, never by index; ragged row -> `GRAB_BAD_ROW` with the line. Caps: 3 MB, 10,000 rows. Header only, no rows -> `GRAB_NO_ROWS` (see Decisions for BOSS, item 1). One Store ID per file or `GRAB_MIXED_STORES`. Per row: `createdOn` parsed strictly from `d Mon yyyy h:mm AM/PM` into `{ date: 'YYYY-MM-DD', time: 'HH:MM' }` (Manila wall clock, the printed date is the business day); `category` trimmed (real values carry a trailing space) and mapped to `payment | loan | adjustment | advertisement | cancelled`; `subcategory` kept (adjustment kinds: `Deduction - Eater Compensation`, `Withholding Tax Remittance (non-taxable)`, `Compensation - Orders`; loan: `Loan Deduction`, `Loan Disbursal`); `status` mapped `Transferred | Completed | Cancelled`; an unknown category, subcategory or status refuses the file with `GRAB_UNKNOWN_VALUE` naming it (fail safe). Money cells go through `parseDecimalInput(..., { blank: 'null' })` into `Money` (an empty cell is null, distinct from 0; bad number -> `GRAB_BAD_VALUE` with line and column). Output row: `{ line, createdOn, kind, subcategory, status, settlementId | null, amount, discount, netSales, channelCommission, total }` plus `description` only for adjustment rows, trimmed to 200 chars and only the generic text. Never exposed or kept: Transaction ID, Linked Transaction ID, Long and Short Order ID, Booking ID, partner transaction ids, Receiving account, Appeal link, customer refund fields. File fields: `storeId`, `storeName`, `periodFrom`, `periodTo` (min and max `createdOn.date`), `rowCount`, `readerVersion`.
4. `grab-transfers.ts`: `readGrabTransfers(bytes: Buffer): GrabTransfersFile`; the 10-header exact set; never reads Bank Statement Code, Bank Name or Bank Account (they are not even mapped into the output); rows `{ line, settlementId, payoutDate: { date, time }, netTotal, status: 'completed' | 'processing', transferDate | null }`; `storeId`, `storeName`; unknown status -> `GRAB_UNKNOWN_VALUE`; one Store ID per file.
5. `grab-payouts.ts`: pure `tieGrabPayouts(transactions: GrabTransactionsFile, transfers: GrabTransfersFile)` -> per payout `{ settlementId, storeDay (payout date minus one day), netTotal, rowsTotal (exact sum of `total` by Settlement ID, `add(...)`), state: 'tied' | 'differs' | 'waiting_for_rows', difference, rows }` plus `unlistedSettlements` (Transaction rows whose Settlement ID has no Transfers row yet, for example the last day). Refuses if the two files name different Store IDs (`GRAB_MIXED_STORES`). `waiting_for_rows` is the first payout of a month whose orders are in the previous month's file.
6. `foodpanda-workbook.ts`: `readFoodpandaInvoice(workbook: Buffer): Promise<FoodpandaInvoice>` which calls `normalizeXlsx` itself first (yauzl checks plus the re-pack to a stored zip, safe by construction) and then reads the sheets in a worker; `read-excel-file/node` over the Buffer, sheets `Appendix A` and `Appendix B` by name (neither -> `FOODPANDA_NO_SHEETS`; B only is valid: the PandaGO-only invoice, `orders: []`). Header normalisation (one function, tested on every real header): CRLF to LF; cut at the first newline; cut at the first `=`; trim; remove one trailing letter token `(X)` or `(XX)` with optional preceding space (so `Official Document Number(A)` and `(AH)= R+S...` both work and `(Wastage)` survives); collapse spaces; then match the WHOLE normalised text against a canonical table (never first `startsWith`, because `foodpanda Commission` prefixes three headers and `Customer Targeting Fee` two). Layout: 34 columns (has Surcharge Fee and Cancellation Fee) or 32 (has neither); a mix -> `FOODPANDA_UNKNOWN_LAYOUT`. Unknown header -> `FOODPANDA_UNKNOWN_COLUMN` naming it; a required header missing -> `FOODPANDA_MISSING_COLUMN` naming it (required: Invoice Number, Invoice Date, Vendor Code, Order Code, Order Date, Gross Food Value, Sales Revenue After Partner Funded Discounts, Balance to be paid to Partner and the fee columns of the layout). Skip every row with no Order Code (the uncached `=SUBTOTAL` row), never trust `sharedStrings` `uniqueCount`, money cells are JS numbers exact to 2 dp (`money(n)`; a non-exact number -> `FOODPANDA_BAD_VALUE`), percent columns are text and ignored, `Order Date` is a Date at 00:00Z read with UTC fields. Order row: `{ orderDate, reversal: boolean, deliveryMode, customerRefund: boolean, gross (K), vendorVoucher (O), vendorDiscount (P), pandaboxVoucher (Q), revenueAfterDiscounts (R), surcharge (S), withholdingTax (T), waitingTimeFee (U), cancellationFee (V, null in the 32 layout), commission (Y or W), pandaboxFee (Z), targetingFee (AB), campaignFee (AC), taxOnCharges (AD), expandedWithholdingTax (AE), alreadyReceived (AF), cancelledWastage, balance (AH), revenueIdentityDifference, balanceIdentityDifference }`. The two difference fields recompute `R = K+L+M+N-O-P-Q` and the Balance formula for the layout and are returned, never refused on (stage decides). Appendix B row: `{ category, description kind: 'cpc_ad' | 'platform_fee' | 'pandago' | 'other', date: 'YYYY-MM-DD' | null (CPC: the ISO date inside the description; PandaGO: month-first `M.DD.YYYY`), feeMonthNote: string | null (Platform Fee text), vatRate, netTotal, ewt }`. Invoice fields: `invoiceNumber`, `invoiceDate` (the period end), `vendorCode` (from the first order row, else Appendix B; compared case-insensitively; all rows must agree or `FOODPANDA_MIXED_INVOICE`), `partnerName`, `layout`, `orders`, `charges`, `readerVersion`. Caps: 5,000 order rows and 200 charge rows (`FOODPANDA_TOO_MANY_ROWS`). The PDF is not read.
7. `deduction-mapping.ts`: Component I of the design as data: for each Grab category and Foodpanda column the deduction kind (`commission`, `marketing`, `platformFee`, or `none`) and a sign (`cost` or `credit`). Grab: `Channel Commission` -> commission; adjustment rows (withholding tax remittance, eater compensation chargeback, compensation orders) -> platformFee (credit when Total is positive); advertisement rows -> marketing; the discount column and `Amount` -> none (information, staff record net, decision 15); loan rows -> none (loan legs). Foodpanda: Y or W commission -> commission; O, P, Q -> none (information; R already after them); S and AE are credits (balance adds them); T, U, V, Z, AB, AC, AD -> platformFee; Appendix B CPC ads -> marketing; Platform Fee -> platformFee; PandaGO -> none. A column not in the table makes the file refuse (`*_UNKNOWN_COLUMN`). Exports a pure `deductionFor(platform, column)`; no staging logic (slice 4 `stage.ts`).
8. `index.ts`: barrel; `READER_VERSION = 'settlement-intake-reader/1'`; add `export * from './settlement-intake';` with a `// T-511 S3` comment at the end of `packages/domain/src/index.ts`. No `store-match.ts` (design puts it in slice 4; its "not found" sentence must not print a Grab Store ID because `refuse()` redacts UUIDs: noted for slice 4). No README (none tracked in `packages/domain/src/*/`; the header JSDoc carries the overview).

## Decisions for BOSS
1. Header-only Grab file: `GRAB_NO_ROWS` (refuse) rather than an empty result (a wrong file is more likely than a store with no orders in a month). 2. Grab headers are an exact set both ways (a new Grab column stops the file with its name) while Foodpanda requires its known columns and refuses unknown ones too. 4. Unknown Grab category, subcategory or status value refuses the file naming it. 5. Dependency route: scratch lock-only plus copy into `packages/domain/node_modules`, or BOSS replaces the junction. 6. `preflightXlsx` and the inner caps are in this slice (not slice 4). 7. `store-match.ts` stays in slice 4. 8.
