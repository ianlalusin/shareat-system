## Design
**A. Staging stores VAT.** Migration 0244 adds `settlement_other_lines.vat_amount numeric(14,2) NULL` (CHECK finite, >= 0). `stage.ts` computes it for `period_charge` lines with the SAME formula as `vatOnFeesOf` (netTotal x vatRate/100, half up, once) via a shared helper (one copy); `ingest.ts` writes it. NULL = staged before S6c, refused with "re-upload the file to book this charge" (no backlog expected: nothing posts before S7).

**B. `postPlatformCharge(tx, actor, { otherLineId, today? })`** (public signature has no `today`; test seam `postPlatformChargeOnClock`, as S6b). Steps, in order: read the other line unlocked (store from its upload); authorize `record_ar_collection` at that store; lock the upload row/channel (never FOR UPDATE on an append-only table) ; re-read; refuse unless kind `period_charge`, `booked_as 'none'`, `day_line_id` null, `is_current`, `vat_amount` not null, channel receivable code == `CHANNEL_RECEIVABLE_CODE` (until slice 8), total = amount + vat not zero (whole centavos via Money/bigint). Already posted for this line = quiet `{posted:false}`. Date = line_date if its period is open else `firstOpenDateOnOrAfter(line_date, clock)`; null -> plain refusal; never reopen. Entry (source_type `channel_charge`, source_id = charge id, key `channel_charge:{otherLineId}:post`): total > 0: Dr `PLATFORM_FEE_CODE` (6400) fee+VAT (one line, memo says VAT included, bible row 75) / Cr 1220 party channel; total < 0 (platform credit note): reversed. storeId = upload store. Insert `channel_period_charges` row, then audit `channel_charge.posted` (money, high, store scope, owner T-511).

**C. Tables (migration 0244, hand-authored per ADR-012 s5).**
- `channel_period_charges`: id, org_id, store_id, channel_id, other_line_id, upload_id, charge_date, net_amount, vat_amount, total_amount (signed, <> 0, = net+vat CHECK), entry_date, journal_entry_id, description, posted_by, posted_at. UNIQUE (org, other_line_id), UNIQUE (org, journal_entry_id); composite same-org FKs (channel+store, other line, journal entry); append-only ENABLE ALWAYS refuse trigger (23001); RLS ENABLE+FORCE; SELECT+INSERT; registries (rls/triggers/classification purge order, before channels/uploads).
- `channel_settlement_charge_links`: (org_id, settlement_id, charge_id) PK; same-org FKs; append-only trigger; RLS; SELECT+INSERT. History only: a link counts only while its settlement is not voided (read through the parent status, as the S6a legs).

**D. The double-count rule (the BOSS test). `recordChannelSettlement` / `previewChannelSettlement` accept `settleChargeIds: string[]`** (charges the platform netted out of THIS payout; S7 approve passes them; no manual-form UI). Let `C` = Σ their totals (checked: same channel+store, posted, not already linked to a non-voided settlement, serialised by a per-charge transaction advisory lock). In `computeSettlement`: `owedGross = owed + C` (the receivable before the charge credits), `outstandingCleared = min(owedGross, gross)`, 1220 credit = `outstandingCleared − C` (refuse if negative), `difference = (outstandingCleared − C) − (fees + loan + deposit)`; the "nothing outstanding" test uses `owedGross`. Links inserted in the same tx. Void settlement: reverse as today, links stay as history and stop counting.
Worked example (fixtures + test): staff day 10,000 (day fees 2,000 incl. VAT, no loan) and another unsettled day 9,000; weekly charge net 100 + VAT 12 = 112 posted (6400 112 / 1220 Cr 112). Payout deposit = 10,000 − 2,000 − 112 = 7,888. With `settleChargeIds [c]`: Dr bank 7,888, Dr 6400 2,000, Cr 1220 9,888 -> difference 0, no acknowledgement, total 6400 = 2,112 (charge expensed once). WITHOUT it (negative control): a 112 shortfall past tolerance needing acknowledgement, and acknowledging books 6420 = 112 on top of the 6400 = double count.

**E. Readers.** `reports.ts` revenue counts only source_type 'sale': `channel_charge` is expense by account, nothing to change; verify with a test. Platform aging/control read 1220 by party: the credit nets FIFO (test). Dual-run: no new class code; add a test that a `channel_charge` entry is classed by an existing family (V2_ONLY_EVENT) and produces no unclassified item; fix `datedEntries` only if the test shows it must. No void function (out of scope).
