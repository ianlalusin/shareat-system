# Ops — the scheduled jobs, and the step that keeps being skipped

> ⛔ **READ THIS FIRST.** Every scheduled job in this business's history has failed the same way,
> and it was never the code.

| | What happened |
|---|---|
| v1 depreciation | The seed data claims *"auto-generated by the depreciation cron"*. **No such cron ever existed.** It stopped for two months, ₱35,483.98 a month went unbooked, and an **audit** found it — not a person |
| POS holiday calendar | The route shipped. **It was never scheduled.** No store ever had one |
| POS weather | Two `gcloud` regions, a job name that did not match the route name, and output that **echoed the shared secret** into the console |

⭐ **So the code being merged is not the finish line. Installing the timer is.**

---

## The jobs

| Job | Command | Cadence | Why that cadence |
|---|---|---|---|
| Month-end (T-140) | `npm run month-end` | Monthly, 1st | Depreciation and amortisation are per-period |
| **Attendance sweep (T-199)** | `npm run attendance-sweep` | ⚠️ **Hourly** | The cut-off is a wall-clock hour **per store**. A daily timer cannot serve two stores on different hours |

## Installing the attendance sweep

```sh
sudo install -m 644 docs/ops/shareat-attendance-sweep.service /etc/systemd/system/
sudo install -m 644 docs/ops/shareat-attendance-sweep.timer   /etc/systemd/system/
sudo mkdir -p /var/log/shareat && sudo chown shareat:shareat /var/log/shareat

sudo systemctl daemon-reload
sudo systemctl enable --now shareat-attendance-sweep.timer
```

**Verify it is actually armed** — this is the step that has never been done:

```sh
systemctl list-timers shareat-attendance-sweep.timer   # NEXT and LEFT must be populated
sudo systemctl start shareat-attendance-sweep.service  # run it once, now
journalctl -u shareat-attendance-sweep.service -n 50
```

⚠️ **`systemctl enable` without `--now` arms it for the next boot and not for today.** That single
missing flag is the shape of every failure in the table above.

## ⭐ How you find out it stopped — without another cron

`scheduler_runs` records every run, including one that did nothing. But a table nobody opens is not
an alarm, and a watchdog that is itself scheduled can die with the thing it watches.

**So the real alarm reads the DATA, not the scheduler.** The `openShiftsStale` finding on
`/findings` fires when a shift has been open more than two days, and it is derived on read — it is
true whether or not the sweep ever ran, and it is `hard` severity, so it blocks a period close.

⛔ **If that finding keeps appearing, the timer is not installed.** That is the whole design.
